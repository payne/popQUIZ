# How I'd build PQ.N3PAY.net (Pop Quiz)

## 1. Platform: one Worker, one database

Everything fits on Cloudflare's free plan.

| Need | Cloudflare piece | Free-tier limit that matters |
|---|---|---|
| The web app (HTML/JS/CSS) | **Workers Static Assets** | Static file requests are free and don't count against Worker limits |
| The API | **Worker** (with the Hono router) | 100k requests per day |
| Quizzes, people, answers | **D1** (SQLite) | 5 GB, 5M rows read per day, 100k rows written per day |
| Deleting old quizzes | **Cron Trigger** | Included |
| Stopping bots from creating quizzes | **Turnstile** | Free |

I'd skip **KV**: the free tier allows only 1,000 writes a day. I'd also skip WebSockets/Durable Objects at first, because polling every 10–15 seconds on the results page is simpler and well within the limits.

You'd point `pq.n3pay.net` at the Worker as a Custom Domain, which assumes n3pay.net's DNS is already on Cloudflare. You'd deploy with `wrangler deploy`.

## 2. Question pools: static JSON, not the database

- NCVEC publishes the pools as public-domain .docx files. Today (Nov 2026) the current pools are:
  - **Technician 2026–2030** (took effect July 1, 2026)
  - **General 2023–2027**
  - **Extra 2024–2028**
- A build script turns each .docx into JSON, for example `tech-2026.json`, shaped like `{id:"T1A01", group:"T1A", q, answers:[A,B,C,D], correct:"C", figure:"T-1"}`. The figure images (T-1, G7-1, E6-1 and so on) are extracted to `/figures/`.
- These files are served as static assets, so they're cached at the edge and never use database reads.
- A **full exam** follows the FCC rule: one question from each group. That gives 35 for Technician, 35 for General and 50 for Extra. Passing is 74%: 26, 26 and 37 correct.
- A **partial quiz** lets you pick N questions, optionally from chosen subelements (e.g., "10 from T5 – Electrical principles").

## 3. Everyone gets the same questions in the same order

The server builds the quiz once and stores the result. Clients never shuffle anything.

```
POST /api/quiz  {pool:"tech", mode:"full"|"custom", count, subelements}
→ server picks questions + shuffles answer order once
→ stores: [{qid:"T1A01", order:[2,0,3,1]}, …]
→ returns { code: "K7XM2P" }
```

- Each quiz gets a 6-character code that's easy to read aloud: no 0/O or 1/I.
- The share link looks like **`pq.n3pay.net/K7XM2P`**.
- Each phone downloads the stored question list and the pool JSON, then puts them together locally. Everyone sees identical questions in identical order.

## 4. Who's taking the quiz (no accounts)

- When someone joins, they enter a **call sign or nickname**.
- The server returns a random **participant token**, which is saved in localStorage under `pq:K7XM2P`.
- That token is the person's identity for that quiz. Refreshing the page, closing the tab or losing signal doesn't lose their place.
- The person who started the quiz gets a creator flag, which lets them do things like close the quiz.

## 5. localStorage + D1 sync (works on bad cell signal)

- Each answer is written to **localStorage first**, so the interface responds instantly. It's then sent to `PUT /api/quiz/:code/answer` with `{qIndex, choice}`.
- Answers that fail to send wait in a queue and retry when the page is back online or visible again.
- The server stores the answer and **ignores later changes** after the person submits.
- When the app starts, it loads localStorage first and then reconciles with the server, so the same person can pick up on another device if they want.

## 6. Database schema (D1)

```sql
quizzes(code PK, pool, pool_version, mode, items_json, created_at, creator_pid, closed_at)
participants(pid PK, code FK, display_name, joined_at, finished_at, score)
answers(pid, q_index, choice, answered_at, PRIMARY KEY(pid, q_index))
```

**Write budget:** a 35-question exam with 10 people is about 400 rows written. 100k a day is plenty.

## 7. Results and comparing with others

This is the part that gets people talking.

- **Your score:** for example "29/35 (83%) PASS ✅", plus a list of the questions you missed and the correct answers.
- **Leaderboard:** each person's score, pass/fail, and time taken.
- **Question-by-question breakdown:** for each question, a bar showing how many people chose A, B, C and D, with the correct answer marked. The questions most people missed are sorted to the top. That's where the discussion starts ("Why did 6 of us pick B on T5C03?").
- **No peeking:** you can't see other people's answers until you've submitted your own. The API enforces this.
- **Live updates:** the results page polls every 10–15 seconds while others are still working.

## 8. Screens and the hamburger menu

- **Home:** pick Technician / General / Extra, then Full exam or Custom (number of questions and subelements), then Start.
- **Join** (`/K7XM2P`): enter call sign, then start.
- **Question screen:** "Q 7 of 35" with a progress bar, the question, an optional figure (tap to zoom), and four large tappable answer buttons. Prev/Next, plus a grid to jump to unanswered questions.
- **Hamburger menu ☰:**
  - **Share this quiz:** uses the phone's native share sheet, so texting is one tap. On computers it falls back to Copy link plus an `sms:` link.
  - **QR code:** for people in the same room at a club meeting.
  - Who's in / their progress (e.g., "Bob: 22/35").
  - Results.
  - Start a new quiz.
  - Light/dark theme.
- **Layout:** designed for phones first using CSS Grid and `clamp()` font sizes. It's one column on phones, and on tablets and computers the question list sits beside the question. All buttons are at least 44 px tall.
- **Optional:** a PWA manifest so people can add it to their home screen.

## 10. Trade-offs I'd decide up front

1. **Answer keys are public anyway.** The pools are published with their answers, so I'd still check answers on the server (to prevent spoilers and keep scores honest) but not treat it as security.
2. **Polling instead of real-time.** It's simpler and cheaper. If you later want a mode where the leader moves everyone to the next question together, I'd add a Durable Object with WebSockets, which the free plan also allows.
3. **Data retention.** A daily cron job deletes quizzes older than 30 days.
